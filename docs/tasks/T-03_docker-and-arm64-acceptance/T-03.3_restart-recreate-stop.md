## Goal

Show the container survives a restart and a recreate and that shutdown is clean (F16 was only read, never run in Docker).

## Steps

1. `docker --context desktop-linux restart oblivion-speaker`: healthy again.
2. Recreate it through the tool (`update` or a second `deploy`: `docker rm -f` then `docker run`): healthy; the `.env` mounted again.
3. A playback in progress (a paced 20 s request), then `docker stop`: time it; PID 1 is `python main.py`, uvicorn gets SIGTERM, the lifespan calls `stop_playback`; expect well under 10 s, the log has `Shutting down: releasing the speaker`, exit code recorded (`docker inspect`), no kill.
4. Start again: `/available` true, a new request plays.

## Acceptance criteria

Steps 1 to 4 behave as written; the time of `docker stop` and the exit code are recorded.

## Result (2026-11-10)

`docker restart oblivion-speaker`: healthy in **0.9 s**. **Recreate** through the tool (a second `deploy`): **25.3 s**, a new container, healthy at once. **`docker stop`:** **Finding (not fixed):** `docker stop` with a playback in flight waits for it, because uvicorn's graceful shutdown waits for the open request: with a 20 s playback and a 30 s grace period it took 18.55 s and ended with exit code 0 and the cleanup (`Shutting down: releasing the speaker`); with Docker's default 10 s grace period it took 10.49 s and was killed (exit code 137, the cleanup logs never appear, the client got an incomplete read). One earlier run, with a 30 s playback started 1 s before the stop, ended in 1.64 s with exit code 137 and only the line `Shutting down`: that run is not explained (it was not repeated). `docker start` after a stop: healthy in 2.1 s. The plan expected a stop in well under 10 s with the cleanup logged: that is true for an idle speaker (the lifespan runs `stop_playback`, as read in F16) and not for one with a playback in flight, which is the case that matters; it is a finding for the maintainer, not fixed here (register R-16).

## Addendum (2026-11-10): the finding was fixed

**Fixed 2026-11-10:** `main_flow/http.py` passes `timeout_graceful_shutdown=GRACEFUL_SHUTDOWN_SECONDS` (5 s) to uvicorn, which now cancels the open requests after 5 s and runs the lifespan cleanup. Test first (`tests/main_flow/test_shutdown.py`, failing on the old code), 4 of 4 one-line mutations caught. Re-run in Docker with Docker's default 10 s grace period: with a 20 s playback in flight `docker stop` took **5.73 s** and ended with exit code **0**; the log shows `Shutting down: releasing the speaker`, `Speaker playback stopped` and `Server stopped; releasing speaker`; the sender got an incomplete read (the playback was cut by the stop, as it must be). Same uvicorn ERROR line for the cancelled request. This closes the part of the plan that was not proven: a stop with a playback in flight.
