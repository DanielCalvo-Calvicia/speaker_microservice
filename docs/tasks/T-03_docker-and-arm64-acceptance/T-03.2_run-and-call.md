## Goal

Run the container with `SPEAKER_BACKEND=null` and call it through the published address as Brain would, including a stream faster than real time.

## Steps

1. With the maintainer's yes, start the container. Deploy output: `speaker: healthy and available, warning: <reason that says null>`, not a failure. The log has the line that names the backend (T-01.4).
2. `GET /health`, `/ready`, `/available`: 200; `/available` has `is_available: true` and the null note; the bind inside is `0.0.0.0` and the published address was used.
3. `POST /process/stream/set?sample_rate=24000&channels=1` with a generated NDJSON body of 3 s of silence or a tone sent as fast as possible (no file of anyone's voice): the answer stream has `stream_started` then `completed`; with pacing the call lasts about 3 s (not instant), and the request is fully drained (no back-up). A raw-PCM body variant too.
4. A second request while the first runs supersedes it (ADR-008); an invalid format is 422 before the stream; an empty body behaves like the real adapter's route test.
5. The container log has counts only, no audio.

## Acceptance criteria

Every call answers as listed; timings and counts recorded.

## Result (2026-11-10)

Run on the container of T-03.1 through `127.0.0.1:8003` with `call_spk.py` from the speaker venv (it builds the bodies with the `contracts` codec; the audio is silence, nothing is played). `/health` 200; `/ready` `is_ready: true`, `pending_reason: null`; `/available` `is_available: true` with the null note. A Brain-style NDJSON body (`stream_started`, 3 s of PCM16 silence as 4,800-byte `partial` events all handed over at once, `completed`): **200**, the answer decodes with `SPEAKER_OUTBOUND` (`stream_started`, `completed`, messages "Playback stream started" and "Playback session finalized successfully") and took **3.06 s**, so the request is drained and paced, not instant; a raw PCM body of 2 s took **2.04 s**; `sample_rate=0` **422**; an empty body **200**; a 20 s playback replaced after 1.5 s by a 1 s one: the second **1.02 s**, the first ended after **1.64 s** with "Playback session superseded by new request"; `/available` after: still true. The container log has the warning `Speaker backend is null: audio is discarded` once and 0 lines that match key, secret, token or password. The pipeline check of the workspace was run natively (84 passed, 18 skipped) and does not use this container.
