## Goal

Build the speaker image from a scratch deployment; record the time and the size.

## Read first

The rules of [T-03](T-03_docker-and-arm64-acceptance.md), `deployment/docker/service.Dockerfile`, `docker_runtime.prepare_context` (the build-context filter).

## Files

None changed. Scratch folders only.

## Steps

1. With the maintainer's yes, make the scratch deployment and run `oblivion.py deploy --host robot -s speaker --dry-run`, then without `--dry-run` (this builds: network, a few minutes).
2. Record: build time, image size (`docker --context desktop-linux images`), the apt packages installed and whether `libportaudio2` is still in the image although `null` does not import `sounddevice` (the cost in MB).
3. The build context: no `.env*`, no `windows/`, no `.git` (names only).

## Acceptance criteria

The image builds; time and MB recorded; the context holds none of the excluded names.

## Result (2026-11-10)

Run with the maintainer's "go", with the same scratch method as the microphone's T-07.1 (a git repo made from a copy of the working tree without `windows/`, `.git`, `.env*` and caches, commit `92bee7d`; a scratch config folder with `local/speaker.toml` carrying only `git`, `branch` and `runtime = "docker"`; nothing for the backend, so the catalogue preset applied; the maintainer's `config/local/` untouched). `oblivion.py validate` accepted Docker for a speaker on Windows and `env` showed `SPEAKER_BACKEND=null` from the layer `catalogue`. The `deploy` took **23 s** (base image cached); `docker build` carried `--build-arg APT_PACKAGES=libportaudio2 portaudio19-dev` (no `libsndfile1`) and no `PREPARE`; **0** `Building wheel`; installed fastapi 0.136.1, uvicorn 0.47.0, python-dotenv 1.2.2, sounddevice 0.5.5, contracts-microservice 0.16.0 and `shared-logging 0.1.0` from `libs/` (**no numpy, no soundfile, no websockets**: the requirements split was right); Python 3.12.16. Image `oblivion/speaker:local` **224 MB**; layers: pip install 21.2 MB, apt install 9.7 MB (`libportaudio2` and `portaudio19-dev` stay in the image although `null` never imports `sounddevice`: a small cost, and the catalogue's `apt` list is per service), the copy of the tree 1.1 MB. The build context held no `.env*`. The `docker run` line has `-p 127.0.0.1:8003:8003`, the `.env` as a read-only bind mount at `/app/.env` and no `--device`. The deploy ended with `speaker: healthy and available, warning: null sink (SPEAKER_BACKEND=null): audio is discarded, nothing is played`: the speaker, which could not even start without an output device, now deploys and passes the readiness check on a machine without a sound card.
