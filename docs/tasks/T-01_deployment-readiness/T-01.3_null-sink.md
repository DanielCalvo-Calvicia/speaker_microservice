## Goal

An `AudioPlaybackPort` that plays nothing but behaves like the real one for its caller: it drains the whole request stream, takes the time the audio would take (if Q01-3 says so), supports supersession and `stop_playback`, and returns the same results (R-1).

## Specification

- `play(audio_format, audio_stream, on_started)`: calls `on_started` with `success=True` ("Playback stream started"), reads **every** chunk of the stream (a sender faster than real time must not back up), counts bytes, and, when pacing is on, waits so that the call ends when real playback of the same audio would (duration = bytes / (rate * channels * 2); the clock is the event loop's, injectable in tests so no test sleeps); on end returns `success=True` ("Playback session finalized successfully", the same message as the real one).
- A new `play` supersedes the running one (ADR-008), and `stop_playback` ends it at once and is idempotent; both are the same observable behaviour as the real backend.
- It keeps **no audio** (Q01-7); it logs the byte and chunk counts at the end (constant message, keyword fields), never the data.
- `check_readiness` returns ready with the note decided in T-01.4.
- It lives in `infrastructure/outbound/null_playback/` and imports nothing from `sounddevice_playback/` that imports `sounddevice`.

## Acceptance criteria

Tests: the stream is drained completely (even when the consumer is much faster than real time); with pacing the call takes the audio's duration on a fake clock, without it returns at once; a new `play` supersedes; `stop_playback` is idempotent; empty body; the events/DTOs are identical in shape to the real backend (compare against the real adapter's result for the same stream with the existing fake driver); an error in the stream is returned as `success=False` like the real one. The whole suite passes; counts of ruff and mypy findings not worse than F2.

## Result (2026-11-10)

Done. `infrastructure/outbound/null_playback/null_audio_playback.py` (`NullAudioPlayback`) written against `tests/infrastructure/test_null_audio_playback.py` (15 tests, a fake clock so none sleeps): the whole stream is read however fast the sender is (1000 chunks), the call lasts the duration of the audio when the sender is faster than real time (3 s, a duration that is not a multiple of the 0.1 s poll, stereo 48 kHz), a sender slower than real time is not made to wait more, an error in the stream is returned as `success=False` and is not paced, a new `play` supersedes the running one (which ends with the real adapter's message, stops reading its stream, and does not end the newer playback when it finishes), `close()` is idempotent and stops a running playback, readiness carries the note. It keeps no audio (Q01-7), logs counts only, and has no environment variable for pacing (the default is paced; tests build it with `realtime=False`). Mutations of the adapter: 16 of 18 caught on the first run; two tests were added for the two that were missed (a replaced playback must stop reading its stream; a duration that is not a whole number of polls is not overshot) and both are caught, so 18 of 18. Not run: the same through HTTP with a long reply and Docker (T-03.2).
