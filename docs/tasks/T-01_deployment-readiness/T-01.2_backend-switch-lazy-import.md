## Goal

Choose the playback backend in the composition root from `SPEAKER_BACKEND`, **before** the `sounddevice` driver module is imported, so a machine without PortAudio (and without a sound card) can start (R-1, R-2; F5, F6).

## Specification

- `SPEAKER_BACKEND` unset or `real`: exactly today's behaviour, including the failure when there is no device (`SpeakerUnavailable` at build); unit tests unchanged apart from the patch target.
- `null`: no import of `sounddevice` anywhere on the path from `main.py` to a running app. A test makes `sounddevice` unimportable (`monkeypatch.setitem(sys.modules, "sounddevice", None)`) and builds the app with `null`.
- Tests first: show the new test fails on the old code (the old code crashes at import or at build).

## Acceptance criteria

The old tests pass; the new tests pass; `null` builds with `sounddevice` unimportable; an unknown value fails naming the variable; ruff and mypy counts are not worse than F2; the documents are updated.

## Verification

`windows\Scripts\python.exe -m pytest`; ruff and mypy with the microphone venv; one-line mutations (default flipped, the lazy import moved to the top, the branch inverted) are all caught.

## Notes

The null sink itself is T-01.3; this task may introduce a minimal placeholder only if T-01.3 cannot be written in the same change, and then says so.

## Result (2026-11-10)

Done. Tests first (they failed on the old code: no `backend` field, no `NullAudioPlayback`): `tests/infrastructure/test_config.py` (2 new) and `tests/composition_root/test_backend_selection.py` (6). Then `SpeakerConfig.backend` (`SPEAKER_BACKEND`, default `real`, case and spaces ignored, any other value raises `ValueError("SPEAKER_BACKEND must be one of real, null, not 'x'")`) and `new_audio_playback`: it returns the null sink for `null`, with one warning `Speaker backend is null: audio is discarded`, and imports `SoundDeviceDriver` only on the `real` branch. The two container tests that patched `speaker_dependencies.SoundDeviceDriver` now patch the driver module (`test_http_container.py`, `test_tracing.py`). `null` builds the whole app with `sounddevice` made unimportable (`sys.modules["sounddevice"] = None`) and never imports the driver module; `real` (default) with no `sounddevice` raises `ImportError`; `real` with a stub and no device still fails with `sounddevice bootstrap failed` (the old behaviour, on purpose). `SPEAKER_BACKEND` is in `.env.example` and `deployment/config/services/speaker.toml` was regenerated. Mutations of the config and the wiring: 9 of 9 caught. `ruff` (microphone venv): one new import-order finding in `audio_playback_dependency.py` was fixed (`--select I001` on that file only); no new finding. `ADR-012` and the documents of the table in `CLAUDE.md` are updated.
