## Goal

Decide what happens with `runtime = "docker"` for an audio service on a Windows host (R-11, F11), then do it. **It is the same change as microphone T-06.4: make it once, in `deployment/domain/rules/host_validation.py`, for every audio service.**

## The question (in [Q01](../../questionnaires/Q01_before-the-deployment-tasks.md))

Keep the rule that rejects Docker for an audio service on Windows, and may a service whose resolved backend is `null` run in Docker on Windows? Or implement the per-machine `mode = "local"` override of the decision of 2026-11-04 ([ADR-011](../../decisions/ADR-011-windows-speaker-runs-natively.md))? *Recommended: keep the rejection, allow `null`.*

## Resolution

*Answered 2026-11-09 (Q01-4, "Recommended"): keep the rejection of Docker for an audio service on Windows, and allow it when the resolved backend is `null` (ADR-011 gets a dated update; no per-machine `mode`). The code change below is one change with microphone T-06.4: make it once.* (Original instruction, kept: when answered: copy the answer here with its date, add a dated update to ADR-011, update R-11. If `null` in Docker on Windows is allowed: `host_validation.py` lets the rule pass when the service's resolved env says the null backend (read through `resolve_env`, not by name), with tests that `real` is still refused and `null` is accepted for the speaker (the microphone's tests cover `sim`); `deployment/docs/DEPLOYMENT.md` says so. If not: this task is `done` without code and T-03 names the manual route (`docker build` with the tool's Dockerfile and `docker run` with the flags `--dry-run` prints).

## Result (2026-11-10)

Done, in the same change as the microphone's T-06.4 (see its Result): `ServiceSpec.simulated_when`, `domain/rules/hardware.py` `uses_sound_device`, `host_validation` and `docker_runtime.start`. For the speaker (`simulated_when = { SPEAKER_BACKEND = "null" }`): `runtime = "docker"` on a Windows host is accepted on `null` and refused on `real` (the message names `SPEAKER_BACKEND = 'null'` as the alternative); a Docker speaker on Linux gets `--device /dev/snd` only on `real`. Tests in `tests/test_simulated_hardware.py` (2 new for the speaker; the old "an audio service with no simulated backend is always refused" test now uses the speaker with its `simulated_when` taken away as the stand-in). ADR-011 has a dated update; register R-11 is updated.
